# 단어장 관리 인수인계 (JA Quiz Wordbooks)

이 문서는 **일본어 단어 암기·시험 웹앱(JA Quiz)** 의 단어장(wordbook) 데이터를 관리·유지보수하는 업무를 넘겨받는 담당자를 위한 안내서입니다. 코드를 몰라도 이 문서만 보고 단어장을 추가·수정·검증할 수 있도록 작성했습니다.

- 앱 주소: <https://d2ceng.github.io/WEB-JA-Quiz/>
- 저장소: `d2cEng/WEB-JA-Quiz` (GitHub)
- 앱 본체: `index.html` (단일 파일 앱)
- 단어장 데이터: `data/` 폴더

| 문서 | 언제 보나 |
|------|-----------|
| **[단어장-데이터-구조.md](단어장-데이터-구조.md)** | **필드명·타입·허용값** 등 스키마를 확인할 때 (가장 먼저) |

| `node tools/n2-check.mjs <파일>` | 작성·수정 후 검사 |

## 1. 이 업무가 하는 일

- 앱에서 학습하는 **단어장(JSON 파일)** 을 만들고, 고치고, 품질을 점검합니다.
- 새 주제의 단어장(예: `JLPT N2 동사`, `여행 회화`)을 추가합니다.
- 기존 단어의 오탈자·뜻·예문·레벨·품사를 바로잡습니다.
- 단어장을 앱의 **📦 불러오기** 목록에 등록합니다.

단어장은 **순수 데이터(JSON)** 이므로, 앱 코드(`index.html`)는 건드리지 않고 `data/` 안의 파일만 다루면 됩니다.

---

## 2. 파일 구성

| 파일 | 역할 |
|------|------|
| `data/wordbooks.json` | **매니페스트**. 앱의 📦 불러오기 드롭다운에 뜨는 단어장 목록. 이름과 파일명을 연결한다. |
| `data/*.json` | **단어장 파일** (현재 12개). 형식 기준은 `words.sample.json`(26단어). |
| `data/idioms/` | **관용구·숙어 데이터.** 단어장과 **스키마가 완전히 다름** (`jp`·`hira`·`ko`·`en`·`ex`). `index.json`이 분류 목록. |
| `tools/n2-check.mjs` | 단어장 검사 도구. 작성·수정 후 실행. |
| `index.html` | 앱 본체. 내부에 **시드 단어**(오프라인 기본 데이터)가 들어 있음. 보통 손대지 않음. |

> 새 단어장을 만들면 `data/`에 `<이름>.json`으로 넣고, `data/wordbooks.json`에 한 줄 등록하면 끝입니다.
> 필드명·타입·허용값은 **[단어장-데이터-구조.md](단어장-데이터-구조.md)** 를 보세요.

## 3. 단어장 JSON 형식

각 단어장 파일은 아래 구조를 따릅니다.

```json
{
  "version": 1,
  "name": "표시 이름 (선택)",
  "words": [
    {
      "id": 1,
      "kanji": "明ける",
      "hiragana": "あける",
      "korean": "날이 밝다,(기간이) 끝나다",
      "level": "N4",
      "pos": "2그룹동사",
      "example": "夜が明ける。,梅雨が明ける。"
    }
  ]
}
```

### 필드 설명

| 필드 | 필수 | 설명 |
|------|:---:|------|
| `id` | 선택 | 단어 고유 번호. **비워도 됨** — 앱이 자동으로 1부터 매깁니다. 넣는다면 파일 안에서 겹치지 않게. |
| `kanji` | ✅ | 간지 표기. 간지가 없는 단어(예: `そして`)는 **히라가나와 동일하게** 적습니다. |
| `hiragana` | ✅ | 읽는 법(히라가나). |
| `korean` | ✅ | 한글 뜻. 뜻이 여러 개면 **쉼표(,)** 로 구분. |
| `level` | 권장 | JLPT 레벨: `N5`·`N4`·`N3`·`N2`·`N1`. |
| `pos` | 권장 | 품사. 아래 4번 참고. |
| `example` | 권장 | 예문. 뜻이 여러 개면 **쉼표(,)** 로 구분해 뜻과 1:1로 맞춤. |

### 여러 뜻 · 예문 규칙 (중요)

`korean`과 `example`은 **쉼표로 나눈 개수와 순서가 서로 대응**합니다.

```json
"korean":  "받다,(시험을) 치르다",
"example": "電話を受ける。,試験を受ける。"
```

- 위 예시는 "받다 → 電話を受ける。", "(시험을) 치르다 → 試験を受ける。" 로 짝지어집니다.
- 뜻이 1개면 예문도 1개(또는 생략). **뜻 개수 > 예문 개수** 여도 동작하지만, 가능하면 개수를 맞춰 주세요.
- 일본어 문장부호 마침표는 `。` 를 씁니다. 쉼표 구분자는 반드시 **반각 쉼표 `,`** (일본어 `、` 아님)를 사용하세요.

## 4. 품사(pos) 표기 규칙

기본은 **한국어 표준값**을 씁니다. 표준값은 **15개**입니다.

`1그룹동사` · `2그룹동사` · `3그룹동사` · `い형용사` · `な형용사` · `명사` · `부사` · `접속사` · `조사` · `감탄사`
· `관용어` · `복합동사` · `연어` · `사자성어` · `속담`

- 영어·일본어·로마자로 적어도 앱이 자동 인식합니다(대소문자·공백·하이픈 무시).
  예: `Group 1 verb`, `godan`, `i-adjective`, `noun`, `名詞`, `ichidan` …
  **별칭 전체 목록은 [단어장-데이터-구조.md](단어장-데이터-구조.md#5-pos-표준값과-별칭-전체) 5번 표**에 있습니다.
- 파일 안에서는 **한국어 표준값으로 통일**하세요(검색·필터 일관성).
- 표에 없는 값은 앱이 그대로 표시합니다(오류는 아니지만 필터에서 따로 묶입니다).
- 품사는 4지선다·N2 `用法`의 **보기를 고르는 기준**이라 정확할수록 문제 품질이 올라갑니다.

레벨(`level`)은 `N5`~`N1` 중 하나로 통일합니다.

## 5. 작업 절차

### A. 새 단어장 추가

1. `data/<주제>.json` 파일을 3번 형식으로 작성. (파일명은 영문·하이픈 권장: 예 `jlpt-n2-verbs.json`)
2. `data/wordbooks.json`의 `wordbooks` 배열에 항목 추가:
   ```json
   { "name": "JLPT N2 동사", "file": "jlpt-n2-verbs.json" }
   ```
   - `name` = 드롭다운에 보일 이름, `file` = `data/` 안의 파일명.
3. 6번 검증 → 7번 반영.

### B. 기존 단어 수정

1. 해당 `data/*.json`을 열어 단어를 고칩니다.
2. 쉼표 뜻/예문 짝, 품사·레벨 값 확인.
3. 6번 검증 → 7번 반영.

### C. AI로 초안 만들기 (빠른 방법)

앱 화면 **단어 DB → 📄 JSON 단어장 파일 만드는 법 → 🤖 AI로 만들기** 에서 주제를 넣고 **프롬프트 복사** → ChatGPT/Claude 등에 붙여넣으면 이 형식에 맞는 JSON 초안을 받을 수 있습니다. 받은 결과는 반드시 6번으로 검증하세요.

## 6. 검증 체크리스트

반영 전에 아래를 확인합니다.

- [ ] **JSON 문법이 유효**한가? (쉼표 누락/중복, 따옴표 짝, 마지막 요소 뒤 쉼표 금지)
  - 빠른 확인: 아래 명령
    ```bash
    for f in data/*.json; do python3 -m json.tool "$f" >/dev/null && echo "OK  $f" || echo "ERR $f"; done
    ```
- [ ] 모든 단어에 `kanji`·`hiragana`·`korean`이 있는가?
- [ ] 간지가 없는 단어는 `kanji`를 히라가나와 같게 적었는가?
- [ ] `korean`/`example`의 **쉼표 구분자가 반각 `,`** 인가? (전각 `、` 아님)
- [ ] `level`이 `N5`~`N1` 범위인가?
- [ ] `pos`가 4번 표준값(또는 인식되는 별칭)인가?
- [ ] (새 단어장) `wordbooks.json`에 `file`이 정확히 등록됐고, 실제 파일명과 일치하는가?
- [ ] **N2 문제 생성 검사를 통과하는가?**
  ```bash
  node tools/n2-check.mjs data/<파일>.json
  ```
  ❌(막힘) 표시가 없어야 하고, `文脈規定·用法` 생성률이 80% 이상이면 좋습니다.
  자세한 기준은 [단어장-N2-작성가이드.md](단어장-N2-작성가이드.md) 참고.

## 7. 앱에 반영하는 법 (배포 흐름)

이 저장소는 **GitHub Pages** 로 자동 배포됩니다. `main` 브랜치에 반영되면 잠시 후 <https://d2ceng.github.io/WEB-JA-Quiz/> 에 그대로 적용됩니다.

권장 흐름:

1. 새 브랜치에서 `data/` 파일을 수정/추가.
2. 커밋 & 푸시.
3. **Pull Request** 생성 → 리뷰 → `main` 머지.
4. 몇 분 뒤 웹앱의 **단어 DB → 📦 불러오기** 목록/데이터에 반영됨.

> 📦 불러오기는 **http(s)로 열었을 때만** 보입니다. `index.html`을 파일로 직접 열면(오프라인) 이 기능이 숨겨지고, 대신 **가져오기(Import)** 로 JSON 파일을 직접 넣습니다. 즉 단어장 파일만 있으면 온라인·오프라인 모두 사용 가능합니다.

## 9. 주의사항 · 알려진 이슈

- **`korean` 안의 쉼표는 구분자입니다.** 뜻에 쉼표를 쓰면 여러 뜻으로 쪼개집니다.
  현재 `words.en.json`은 9,902단어 중 8,437개(85%)가 영어 뜻의 쉼표 때문에 여러 뜻으로 분해되고,
  그중 2,848개는 예문 개수와 맞지 않습니다. **가장 큰 데이터 부채**이며, 정리하려면 뜻 나열을 `·`나 `/`로 바꿔야 합니다.
- **`words.en.json` 예문 부족**: 6,242단어에 예문이 없어 N2 문장형 문제가 35%만 생성됩니다.
- **이름 표기**: 표시 이름은 매니페스트의 `name`이 우선입니다. 파일 내부 `name`과 다르면 헷갈리니 맞춰 두세요.
  (`words.sample.json`은 내부 `name`이 없어 매니페스트 이름을 씁니다 — 정상입니다.)
- `id`는 생략 가능하지만, 한 파일 안에서 직접 넣을 경우 **중복 금지**.
- 단어 수가 아주 많아지면 파일이 커집니다. 주제별로 파일을 나누는 편이 관리에 유리합니다.
- 앱 코드(`index.html`)의 시드 단어는 오프라인 기본값입니다. 단어장 관리 업무에서는 보통 수정하지 않습니다.
