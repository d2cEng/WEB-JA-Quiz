# 단어장 작성 가이드 — JLPT N2 문제가 잘 나오게 만들기

퀴즈의 **N2 어휘** 단계는 별도의 문제 은행이 없습니다. **단어장 JSON만 가지고 문제를 자동 생성**합니다.
그래서 단어장에 어떤 정보가 어떤 모양으로 들어 있느냐가 문제의 난이도와 자연스러움을 그대로 결정합니다.

이 문서는 "무엇을 넣어야 N2다운 문제가 나오는지"를 정리한 것입니다.
기본 형식·필드 설명은 [단어장-관리-인수인계.md](단어장-관리-인수인계.md)를 먼저 보세요.

---

## 1. 유형별로 필요한 데이터

| 유형 | 문제 모양 | 만들어지는 조건 |
|------|-----------|-----------------|
| 漢字読み | 예문 속 밑줄 단어의 **읽는 법** | `kanji`에 한자가 있고 `hiragana`와 다를 것 |
| 表記 | 밑줄 히라가나의 **한자 표기** | 위 조건 + **예문에 `kanji`가 그대로** 들어 있을 것 |
| 文脈規定 | 예문을 （　）로 비우고 **들어갈 말** | **예문에 표제어가 그대로** 들어 있을 것 |
| 用法 | 그 단어가 **올바르게 쓰인 문장** | 위 조건 + 단어장에 같은 조건을 만족하는 **다른 단어 3개 이상** |
| 言い換え類義 | 밑줄 단어와 **뜻이 가까운 것** | 항상 가능 (한글 뜻만 있으면 됨) |

> **핵심은 예문입니다.** 예문이 없거나 예문에 표제어가 그대로 없으면 5유형 중 3유형이 사라지고,
> 항상 만들 수 있는 **言い換え(뜻 고르기)만 남아 시험이 단조롭고 쉬워집니다.**

---

## 2. 필수 · 권장 필드

| 필드 | 등급 | N2 문제에서 하는 일 |
|------|:----:|---------------------|
| `kanji` | 필수 | 漢字読み·表記의 전제. 한자가 없으면 두 유형이 빠짐 |
| `hiragana` | 필수 | 읽기 정답. 오답은 이 읽기를 비틀어 자동 생성 |
| `korean` | 필수 | 言い換え 정답 + 다른 문제의 보기 |
| `example` | **사실상 필수** | 文脈規定·用法·表記를 만드는 재료 |
| `pos` | 권장 | 보기를 뽑는 기준. 없으면 오답이 엉뚱해짐 (아래 4번) |
| `level` | 권장 | 난이도 표시·범위 지정 |

## 3. 예문 작성 규칙 (가장 중요)

### ① 표제어를 **사전형 그대로** 넣는다

```jsonc
// ✅ 좋음 — 표제어 「明ける」가 그대로 들어 있다
{ "kanji": "明ける", "hiragana": "あける", "example": "夜が明ける。" }

// ❌ 나쁨 — 활용해서 「明けた」가 되면 어간(明け)만 일치한다
{ "kanji": "明ける", "hiragana": "あける", "example": "夜が明けた。" }
```

활용형이면 **表記·文脈規定·用法 세 유형을 못 만듭니다.** (밑줄과 정답이 어긋나 漢字読み도 문맥 없이 출제됩니다.)
자연스러운 문장을 위해 활용이 꼭 필요하면, 그 단어는 문장형 문제에서 빠진다는 점을 감안하세요.

### ② 예문은 **10자 이상**, 문맥이 드러나게

`文脈規定`은 예문에서 단어를 빼고 맞히는 문제입니다. 예문이 짧으면 단서가 없어 **정답이 애매해집니다.**

```jsonc
// ❌ 너무 짧음 — 「（　）がいい。」로는 무엇이든 답이 된다
{ "kanji": "海", "example": "海がいい。" }

// ✅ 문맥이 있음 — 「夏に（　）へ行く。」는 답을 좁힐 수 있다
{ "kanji": "海", "example": "夏に家族で海へ行く。" }
```

현재 단어장 예문 길이 중앙값은 **12~15자**입니다. **8자 이하는 검사기가 경고**합니다.

### ③ 뜻이 여러 개면 예문도 **쉼표로 1:1**

```jsonc
{ "korean": "받다,(시험을) 치르다",
  "example": "電話を受ける。,試験を受ける。" }
```

개수가 어긋나면 뜻에 맞지 않는 예문이 문제로 나올 수 있습니다.

### ④ 한 예문에 표제어는 **한 번만**

여러 번 나오면 첫 번째만 빈칸·밑줄 처리되어 나머지가 정답을 그대로 노출합니다.

## 4. 단어장 구성 규칙 — 用法이 어색해지지 않으려면

`用法`의 오답은 **다른 단어의 예문에 이 단어를 끼워 넣어** 만듭니다.
이때 **품사가 다른** 단어에서 뽑아야 확실히 어색한 문장이 됩니다.

```
목표 단어: 海 (명사)
✅ 품사가 다른 단어에서:  今日はとても海。 / 友達が海。   ← 명백히 틀림 (좋은 오답)
❌ 같은 명사에서:        家がいい。→ 海がいい。         ← 말이 되어 정답이 모호해짐
```

그래서 **한 품사로만 채운 단어장은 用法 문제가 애매해집니다.**

> **규칙: 예문이 있는 단어 중 서로 다른 품사가 최소 3개씩은 섞이게 구성하세요.**
> 명사 위주 주제(메뉴·마트 등)라면 관련 **동사·형용사 몇 개를 함께 넣으면** 해결됩니다.
> 실제로 289단어인 `izakaya-menu.json`은 명사 80%여도 나머지 20%가 충분해 문제없지만,
> 60단어짜리 `transport.json`(명사 95%)·`onomatopoeia.json`(부사 100%)은 경고가 뜹니다.

### 활용형이 자연스러운 주제는 낮게 나오는 게 정상

경어(`keigo.json`)처럼 **정중형이 자연스러운 주제**는 예문이 `いらっしゃいます`·`召し上がります`처럼
활용된 형태라, 사전형 표제어(`いらっしゃる`)와 글자가 달라 `文脈規定·用法`을 만들 수 없습니다.

```
いらっしゃる  ← 표제어(사전형)
先生は研究室にいらっしゃいます。  ← 예문(정중형) : 글자가 달라 매칭 실패
```

여기서 예문을 억지로 사전형(`先生は研究室にいらっしゃる。`)으로 바꾸면 **경어로서 부자연스러워집니다.**
그러니 이런 주제는 생성률 60%대가 정상이고, `漢字読み`·`言い換え`로 출제됩니다.
검사기도 원인이 '활용형'이면 그렇게 안내합니다. **예문 보강 대상은 '예문 없음'이 많은 파일입니다.**

### 그 밖의 구성 주의

- **한글 뜻 중복 금지** — 뜻이 같은 단어는 서로 보기에서 걸러져 선택지가 줄어듭니다.
- **가나·외래어 전용 단어**(オノマトペ, 외래어)는 `漢字読み·表記`가 원천적으로 불가합니다. 정상이며, 이런 주제는 나머지 3유형으로 출제됩니다.
- **최소 4단어** 이상이어야 보기 4개를 채웁니다. 실질적으로는 **30단어 이상**을 권장합니다.

## 5. 검사 도구

작성·수정 후 반드시 돌려 보세요. 앱의 생성 조건을 그대로 옮겨 놓은 검사기입니다.

```bash
node tools/n2-check.mjs                 # data/ 전체
node tools/n2-check.mjs data/foo.json   # 특정 파일
node tools/n2-check.mjs data/foo.json --list   # 문제 단어를 하나씩
```

출력 예:

```
=== data/izakaya-menu.json — 289단어 ===
  생성 가능  漢字読み 82%  表記 80%  文脈規定 96%  用法 96%  言い換え 100%
  ✅ N2 문제 생성에 적합
```

표시 기호

| 기호 | 뜻 | 대응 |
|------|-----|------|
| ❌ 막힘 | 문제를 **못 만든다** (예문 없음/불일치) | 예문을 채우거나 사전형으로 고칠 것 |
| 💡 품질 | 만들어지지만 **쉽거나 어색해진다** | 품사 다양화·예문 늘리기·뜻 중복 제거 |
| ✅ | 적합 | 그대로 사용 |

**목표: `文脈規定·用法` 생성률 80% 이상, ❌ 없음.**

## 6. 새 단어장 체크리스트

- [ ] 모든 단어에 `kanji` · `hiragana` · `korean` 이 있다
- [ ] **모든 단어에 `example` 이 있다**
- [ ] 예문에 표제어가 **사전형 그대로** 들어 있다 (활용 금지)
- [ ] 예문이 **10자 이상**이고 문맥이 드러난다
- [ ] 뜻이 여러 개면 `korean` / `example` 이 **쉼표로 1:1**
- [ ] `pos` · `level` 을 모든 단어에 채웠다
- [ ] 서로 **다른 품사가 3개 이상** 섞여 있다
- [ ] 한글 뜻이 **중복되지 않는다**
- [ ] `node tools/n2-check.mjs <파일>` 이 ❌ 없이 통과한다

## 7. AI로 단어장을 만들 때 붙일 지시문

앱의 **🤖 AI로 만들기** 프롬프트에 아래를 덧붙이면 N2 문제 생성에 맞는 데이터가 나옵니다.

```text
추가 규칙 (JLPT N2 문제 자동 생성용):
1. 모든 단어에 example(예문)을 반드시 넣어라.
2. 예문에는 표제어(kanji)를 활용하지 말고 사전형 그대로 넣어라.
   예: 「明ける」→「夜が明ける。」(O) / 「夜が明けた。」(X)
3. 예문은 10자 이상으로, 그 단어가 아니면 안 되는 문맥을 담아라.
   예: 「海がいい。」(X, 문맥 없음) / 「夏に家族で海へ行く。」(O)
4. 한 예문에 표제어는 한 번만 등장시켜라.
5. 뜻이 여러 개면 korean과 example을 쉼표로 같은 개수·같은 순서로 맞춰라.
6. pos와 level을 모든 단어에 채워라.
7. 명사만으로 채우지 말고, 동사·형용사·부사를 각각 3개 이상 섞어라.
8. 서로 한글 뜻이 똑같은 단어를 넣지 마라.
```

## 8. 참고 — 지금은 쓰지 않는 정보

아래는 **앱이 아직 읽지 않는** 항목입니다. 넣어도 무시되므로 지금은 채울 필요가 없습니다.
다만 이 데이터가 있으면 문제 품질이 올라가므로, 앞으로 기능을 넓힐 때 후보가 됩니다.

| 항목 | 있으면 좋아지는 점 |
|------|--------------------|
| 유의어(`synonym`) | `言い換え類義`를 지금의 한글 뜻 근사 대신 **실제 일본어 유의어**로 출제 가능 |
| 접두·접미사(`affix`) | N2의 여섯 번째 유형인 **語形成(어형성)** 을 만들 수 있음 (현재 미구현) |
| 오용 예문(`wrongExample`) | `用法` 오답을 자동 조합 대신 **사람이 쓴 자연스러운 오답**으로 대체 |

필요해지면 요청해 주세요. 앱과 검사기를 함께 확장해야 합니다.
