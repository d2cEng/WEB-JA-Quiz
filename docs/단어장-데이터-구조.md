# 단어장 데이터 구조 (스키마 레퍼런스)

이 앱이 읽는 **모든 데이터 파일의 필드명·타입·허용값**을 정리한 문서입니다.
값을 어떻게 채워야 좋은 문제가 나오는지(내용 품질)는 [단어장-N2-작성가이드.md](단어장-N2-작성가이드.md),
업무 절차는 [단어장-관리-인수인계.md](단어장-관리-인수인계.md)를 보세요.

> 이 문서는 `index.html`의 실제 코드(`applyWordbook` · `normalizeWords` · `deriveMeanings` · `POS_ALIASES`)에서 추출했습니다.
> 앱을 고칠 때 이 문서도 함께 고쳐야 합니다.

---

## 1. 파일 구성 한눈에

```
data/
├── wordbooks.json          ← ① 단어장 목록(매니페스트). 앱의 📦 불러오기에 뜨는 목록
├── words.sample.json       ← ② 단어장 파일 (여러 개)
├── izakaya-menu.json       ← ②
├── words.en.json           ← ②
├── … (그 외 단어장들)
└── idioms/
    ├── index.json          ← ③ 관용구 분류 목록
    ├── idiom.json          ← ④ 관용구 데이터 (②와 스키마가 완전히 다름!)
    ├── compound.json       ← ④
    ├── collocation.json    ← ④
    ├── yojijukugo.json     ← ④
    └── proverb.json        ← ④
```

**단어장(②)과 관용구(④)는 필드명이 완전히 다릅니다.** 섞어 쓰면 로드되지 않습니다.

## 2. ② 단어장 파일 스키마

### 최상위(top-level)

| 필드 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| `version` | number | 관례 | 현재 `1`. 앱은 검사하지 않지만 항상 넣습니다. |
| `name` | string | 선택 | 단어장 이름. 없으면 매니페스트의 `name`이나 파일명이 쓰입니다. |
| `words` | array | **필수** | 단어 배열. **비어 있으면 로드가 거부됩니다.** |

```jsonc
{ "version": 1, "name": "JLPT N5 단어장", "words": [ /* … */ ] }
```

> 최상위에 `selected` · `schedule` · `progress` · `excluded` · `log` 가 있으면 **학습 진도까지 함께 복원**됩니다.
> 이건 앱의 **내보내기(백업)** 파일 형식입니다. 배포용 단어장에는 넣지 마세요 (9번 참고).

### 단어 객체(`words[]`)

| 필드 | 타입 | 필수 | 기본값·동작 |
|------|------|:----:|-------------|
| `id` | number | 선택 | **비워도 됨.** 없으면 앱이 배열 순서대로 `1,2,3…` 자동 부여. 직접 넣으면 파일 안에서 중복 금지 |
| `kanji` | string | **필수** | 한자 표기. **한자가 없는 단어는 `hiragana`와 똑같이** 적습니다 (`そして` → 둘 다 `そして`) |
| `hiragana` | string | **필수** | 읽는 법(히라가나) |
| `korean` | string | **필수** | **뜻.** 이름은 `korean`이지만 그 단어장의 대상 언어를 넣습니다 (영어 단어장은 영어). 쉼표로 여러 뜻 |
| `level` | string | 권장 | `N5`·`N4`·`N3`·`N2`·`N1` |
| `pos` | string | 권장 | 품사. 표준값·별칭은 5번 표 |
| `example` | string | 권장 | 예문. 쉼표로 뜻과 1:1 대응 |

```jsonc
{
  "id": 1,
  "kanji": "受ける",
  "hiragana": "うける",
  "korean": "받다,(시험을) 치르다",
  "level": "N4",
  "pos": "2그룹동사",
  "example": "電話を受ける。,試験を受ける。"
}
```

**정의된 필드는 이 7개가 전부입니다.** 그 밖의 키(`en`, `note`, `romaji`, `audio` 등)를 넣어도 앱은 무시합니다.

## 3. 앱이 자동으로 하는 정규화

파일을 불러오면 앱이 아래를 자동 처리합니다. **파일에 미리 넣을 필요가 없습니다.**

| 처리 | 내용 |
|------|------|
| `id` 자동 부여 | `id`가 없으면 배열 순서대로 1부터 매김 |
| `pos` 표준화 | 영어·일본어·로마자 별칭을 한국어 표준값으로 변환 (대소문자·공백·하이픈 무시). 모르는 값은 **그대로 둠** |
| `meanings` 생성 | `korean`과 `example`을 쉼표로 쪼개 `[{korean, example}, …]` 를 만들어 붙임 |

### `meanings` — 파생 필드 (파일에 넣지 마세요)

`meanings`는 앱이 메모리에서 만들어 쓰는 값입니다. 저장·내보내기 시 자동으로 제거됩니다.
파일에 적어 두어도 무시되고 덮어써집니다.

---

## 4. ⚠️ 쉼표는 문장부호가 아니라 **구분자**입니다 (가장 흔한 사고)

`korean`과 `example`은 **반각 쉼표 `,`** (또는 전각 `，`)로 쪼개져 **뜻 ↔ 예문이 순서대로 1:1 대응**됩니다.

```jsonc
"korean":  "받다,(시험을) 치르다"          // 뜻 2개
"example": "電話を受ける。,試験を受ける。"   // 예문 2개  → 1:1 대응 ✅
```

그래서 **뜻 안에 쉼표를 쓰면 뜻이 쪼개집니다.**

```jsonc
// ❌ 실제 words.en.json의 사고 사례
"korean":  "greeting, greetings, salutation, salute"   // → 뜻 4개로 분해
"example": "朝、先生にあいさつをしました。"                // → 예문 1개  ⇒ 개수 불일치
```

> 현재 `words.en.json`은 9,902단어 중 **8,437개(85%)** 가 쉼표로 여러 뜻으로 쪼개지고,
> 그중 **2,848개**가 예문 개수와 맞지 않습니다. 뜻을 나열할 때는 `·` 나 `/` 를 쓰거나,
> 진짜 여러 뜻이라면 예문도 같은 개수로 맞추세요.

**예문 구분자 보정:** 뜻이 2개 이상인데 예문이 쉼표로 덜 쪼개졌으면, 앱이 `、` 또는 `。` 로 다시 나눠 봅니다.
그 결과가 **뜻 개수와 정확히 같을 때만** 채택합니다.

**일본어 문장부호 주의:** 예문 안의 일본어 쉼표는 `、`(전각) 이고, 구분자는 `,`(반각) 입니다. 섞지 마세요.

## 5. `pos` 표준값과 별칭 (전체)

왼쪽이 **파일에 쓸 표준값**, 오른쪽은 앱이 자동 인식하는 별칭입니다.

| 표준값 | 인식되는 별칭 |
|--------|----------------|
| `1그룹동사` | group 1 verb, group1 verb, godan verb, godan, u verb, u-verb, 五段動詞, 五段 |
| `2그룹동사` | group 2 verb, group2 verb, ichidan verb, ichidan, ru verb, ru-verb, 一段動詞, 一段 |
| `3그룹동사` | group 3 verb, group3 verb, irregular verb, irregular, 不規則動詞 |
| `い형용사` | i adjective, i-adjective, i adj, i-adj, keiyoushi, 形容詞 |
| `な형용사` | na adjective, na-adjective, na adj, na-adj, keiyoudoushi, 形容動詞 |
| `명사` | noun, 名詞 |
| `부사` | adverb, 副詞 |
| `접속사` | conjunction, 接続詞 |
| `조사` | particle, 助詞 |
| `감탄사` | interjection, 感動詞 |
| `관용어` | 관용구, idiom, idiomatic, 慣用句 |
| `복합동사` | compound verb, compound, 複合動詞 |
| `연어` | collocation, 連語 |
| `사자성어` | four character idiom, yojijukugo, 四字熟語 |
| `속담` | proverb, ことわざ, 諺 |

- 매칭 시 **대소문자와 공백·밑줄(`_`)은 무시**됩니다 (`Group_1  Verb` = `group 1 verb`).
- **하이픈은 정규화되지 않습니다.** 위 표에 있는 하이픈 표기(`u-verb`, `i-adjective`, `na-adj` 등)만 인식되고,
  표에 없는 하이픈 조합(`godan-verb` 등)은 인식되지 않습니다. **되도록 한국어 표준값을 쓰세요.**
- 표에 없는 값은 변환 없이 그대로 표시되며, 품사 필터에서 따로 묶입니다.
  (예: 현재 `keigo.json`에 `기타` 5건이 있습니다.)
- **품사는 4지선다·N2 用法의 보기를 고르는 기준**이라 정확할수록 문제 품질이 올라갑니다.

## `level` 값

`N5` `N4` `N3` `N2` `N1` 다섯 가지를 씁니다. 앱이 강제 검증하지는 않지만,
레벨 배지·범위 지정에 쓰이므로 이 표기를 지키세요.

## 6. ① 매니페스트 `data/wordbooks.json`

앱의 **📦 불러오기** 드롭다운 목록입니다. 새 단어장을 만들면 **여기에 등록해야 목록에 뜹니다.**

| 필드 | 타입 | 설명 |
|------|------|------|
| `version` | number | `1` |
| `wordbooks` | array | 항목 배열 |
| `wordbooks[].name` | string | 드롭다운에 보일 이름 |
| `wordbooks[].file` | string | `data/` 안의 **파일명만** (경로 없이) |
| `wordbooks[].lang` | `"ko"` \| `"en"` | **뜻(`korean` 필드)이 어느 말로 쓰였는지.** 없으면 `"ko"`로 봅니다. |
| `wordbooks[].rev` | string | 내용 해시. **손으로 쓰지 말고** `node tools/sync-manifest.mjs`가 채우게 합니다. |

```jsonc
{
  "version": 1,
  "wordbooks": [
    { "name": "JLPT 샘플 단어장", "file": "words.sample.json", "rev": "1d432r5:836", "lang": "ko" },
    { "name": "JLPT N5–N1 Vocabulary", "file": "words.en.json", "rev": "fek83a:658289", "lang": "en" }
  ]
}
```

> 표시 이름은 **매니페스트의 `name`이 우선**입니다. 단어장 파일 안의 `name`과 다르면 헷갈리니 맞춰 두세요.

### `lang` — 화면 언어와 단어장이 따로 놀지 않게

앱 오른쪽 위 **한/EN** 토글이 `"ko"`면 `lang:"ko"` 단어장만, `"en"`이면 `lang:"en"` 단어장만
📦 불러오기 목록에 뜹니다. 뜻이 영어인 단어장을 한국어 화면에서 고르는 일(그 반대도)이 없어집니다.

- 한국어판 이름은 한국어로, 영어판 이름은 영어로 적으세요. 각각 그 언어 화면에서만 보입니다.
- 같은 내용을 두 언어로 낼 때는 **파일을 나눕니다** — 예: `words.ko.json`(`lang:"ko"`) /
  `words.en.json`(`lang:"en"`). 한 파일에 두 언어를 섞지 않습니다.
- `lang`을 빠뜨리면 한국어판으로 취급됩니다. `sync-manifest.mjs`가 빠진 항목을 경고로 알려 줍니다.

## 7. ③④ 관용구·숙어 데이터 (`data/idioms/`)

**단어장과 스키마가 다릅니다.** 필드명이 `jp` · `hira` · `ko` · `en` · `ex` 입니다.

### ③ `data/idioms/index.json` — 분류 목록

| 필드 | 타입 | 설명 |
|------|------|------|
| `version` | number | `1` |
| `categories[].pos` | string | 분류명. 5번 표의 품사 표준값과 같은 값 (`관용어`·`복합동사`·`연어`·`사자성어`·`속담`) |
| `categories[].en` | string | 영어 표시명 |
| `categories[].file` | string | 이 폴더 안의 파일명 |

### ④ 분류 파일 (`idiom.json` 등)

| 필드 | 타입 | 설명 |
|------|------|------|
| `pos` | string | 이 파일의 분류명 (index.json의 `pos`와 일치) |
| `en` | string | 영어 표시명 |
| `themes` | array | 주제 묶음 |
| `themes[].id` | string | 주제 id (`g1`, `g2`…) |
| `themes[].ko` / `.en` | string | 주제 이름 (한국어 / 영어) |
| `entries` | array | 표현 목록 |
| `entries[].theme` | string | 속한 주제 id (`themes[].id` 중 하나) |
| `entries[].jp` | string | 일본어 표기 |
| `entries[].hira` | string | 読み(히라가나) |
| `entries[].ko` | string | 한국어 뜻 |
| `entries[].en` | string | 영어 뜻 |
| `entries[].level` | string | **JLPT 레벨 `N5`~`N1`.** 단어장으로 불러올 때 `level`로 그대로 들어갑니다 |
| `entries[].ex` | string | 예문 |

```jsonc
{
  "pos": "관용어",
  "en": "Idioms (慣用句)",
  "themes": [ { "id": "g1", "ko": "気 — 마음·기분", "en": "気 — mind & mood" } ],
  "entries": [
    { "theme": "g1", "jp": "気が利く", "hira": "きがきく",
      "ko": "눈치가 빠르다, 센스 있다", "en": "to be thoughtful",
      "level": "N2", "ex": "彼は気が利く人だ。" }
  ]
}
```

### 어법 → 단어장 변환 (암기·퀴즈에서 쓸 때)

어법 탭의 **📚 단어장으로 불러오기**를 누르면 아래처럼 단어장 형식으로 바뀝니다.

| 단어장 필드 | 어법에서 가져오는 값 |
|-------------|----------------------|
| `kanji` | `entries[].jp` |
| `hiragana` | `entries[].hira` |
| `korean` | `entries[].ko` (영어 모드면 `en`) |
| `level` | `entries[].level` |
| `pos` | 파일의 `pos` (분류명) |
| `example` | `entries[].ex` |

> `themes`는 어법 탭의 **묶음 표시 전용**이며 단어장으로 넘어가지 않습니다.
> 한 분류만 불러오면 `pos`가 전부 같아져 N2 `用法` 오답이 애매해집니다.
> **어법 전체**로 불러오면 5개 분류가 섞여 이 문제가 없습니다.

> 주의: `entries[].theme` 는 반드시 `themes[].id` 에 있는 값이어야 합니다. 오타가 나면 그 항목이 어느 묶음에도 안 뜹니다.
> 관용구의 `ko`에 쓰인 쉼표는 단어장과 달리 **분해되지 않습니다** (그냥 텍스트).

## 8. 새 단어장을 추가하는 최소 절차

1. `data/<이름>.json` 생성 — 2번 스키마
2. `data/wordbooks.json` 의 `wordbooks` 에 `{ "name": …, "file": … }` 추가
3. 검사
   ```bash
   node tools/n2-check.mjs data/<이름>.json
   ```
4. 커밋 → PR → `main` 머지 (GitHub Pages 자동 반영)

## 9. 배포용 단어장 vs 내보내기(백업) 파일

같은 확장자지만 용도가 다릅니다.

| | 배포용 단어장 (`data/*.json`) | 내보내기 백업 |
|---|---|---|
| 최상위 필드 | `version`, `name`, `words` | + `selected`, `schedule`, `progress`, `excluded`, `log` |
| 담긴 것 | 단어만 | 단어 **+ 개인 학습 진도** |
| 용도 | 저장소에 커밋해 모두에게 배포 | 기기 이동·백업 |

> **저장소에 커밋하는 단어장에는 진도 필드를 넣지 마세요.** 남의 학습 기록이 덮어써집니다.

## 10. 구조 검사

`tools/n2-check.mjs` 가 이 문서의 스키마를 그대로 검사합니다.

```bash
node tools/n2-check.mjs data/<파일>.json --list
```

검사 항목

| 등급 | 잡아내는 것 |
|------|-------------|
| ❌ 막힘 | `words` 없음/빈 배열, 필수 필드(`kanji`·`hiragana`·`korean`) 누락, `id` 중복 |
| 💡 품질 | 모르는 필드(오타), 타입 오류, `level`이 N5~N1 아님, `pos`가 표준값/별칭 아님, `korean`에 전각 쉼표, 최상위에 진도 필드(`progress` 등) |
| 정보 | `version` 없음, `meanings`를 파일에 넣음, 뜻/예문 개수 불일치 |

## 11. 자주 나는 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| 불러오기 목록에 안 뜸 | `wordbooks.json`에 등록 안 함 / `file` 오타 | 파일명 정확히 등록 |
| 로드 실패 | `words`가 없거나 빈 배열, JSON 문법 오류 | `python3 -m json.tool <파일>` 로 검사 |
